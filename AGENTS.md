# Agent Instructions

These instructions apply to the `mujoco_playground` repository.

## Before Editing

- Always inspect `git status --short --branch` before making changes.
- Preserve user or unrelated dirty work. Do not revert, overwrite, or clean files you did not intentionally change.
- Never run destructive git commands such as `git reset --hard`, `git checkout --`, or broad `rm` commands unless the user explicitly asks for them.

## Branching And Worktrees

- Use stable-release based branches for migration work. The current Digit migration branch is based on `v0.2.0`.
- Prefer sibling worktrees next to this checkout, for example `../mujoco_playground-feature-digit-tests`.
- Do not create worktrees inside this repository.

## Package Management

- Prefer the parent Pixi workspace at `/home/fwu91/Documents/SRL/pixi.toml`.
- From this checkout or a sibling worktree, run Pixi with `pixi --manifest-path ../pixi.toml ...`.
- Keep `brax` and `mujoco_playground` as sibling editable packages. Do not convert either repo into a submodule of the other.
- Keep the regular `old-digit` Pixi environment pinned to stock `brax==0.12.1` for PPO/dynamics baselines. Use the separate `old-digit-l2t` environment when the custom sibling Brax L2T source is needed with the old Digit stack.
- Use `gate-digit-imports` when changing Pixi/env wiring; it proves default imports migrated `mujoco_playground` plus sibling Brax, `old-digit` imports `thirdarm_project` plus stock Brax/JAX/MuJoCo, and `old-digit-l2t` imports `thirdarm_project` plus sibling Brax through `PYTHONPATH`.
- Use `check-digit-package-data` when touching Digit XML/assets or `pyproject.toml`; it checks required Digit files, the Hatch `_src` include rule, and absence of generated/archive files under `digit_v3`.
- Use `check-digit-source-drift` when touching imported Digit source; it compares migrated `digit_v3` against `thirdarm_project` and only allows the documented migration shims, helper/test files, print suppression, and omitted old archive.
- If a local PPO/probe run leaves Digit bytecode under `digit_v3`, run `pixi run --manifest-path ../pixi.toml clean-digit-bytecode`; `gate-digit-migration-smoke` does this at the start and then checks package data again at the end.

## Digit Migration

- Treat Warp as the primary Digit backend.
- Keep JAX support as the secondary compatibility backend.
- Run `gate-digit-warp-smoke` after changes that can affect migrated Digit reset/step behavior; it checks the Warp-primary reference env can load the downloaded dataset, reset, take one zero-action step, and fail on non-finite probe summaries.
- Run `gate-digit-warp-training-smoke` after changes that can affect migrated Digit PPO training. Warp PPO must keep `--use_pmap_on_reset=True`; the non-pmapped reset path leaves large Warp contact buffers without the expected leading device axis.
- Use `gate-digit-migration-smoke` as the local preflight before handing off broad Digit changes; it cleans Digit bytecode, then chains import-provenance checks, package-data checks, source-drift checks, compile, Digit dynamics tests, Warp reset/step smoke, Warp PPO training smoke, and the strict zero-action PPO rule-out gate.
- Use `gate-digit-training-parity` for the practical old/new training acceptance path; it chains the four-update PPO parity gate and deterministic L2T parity gate under the `0.001` tolerance. Use `gate-digit-accepted-parity` when you need the broader acceptance contract: x64 one-step JAX state/control parity, PPO/L2T training parity, single-trajectory policy-behavior parity, and the summarized `/tmp/digit_accepted_parity_report.json`.
- Treat `0.001` as the practical acceptance line for old/new PPO, L2T, and policy-behavior metric diffs. Do not silently apply it to the known normal raw JAX dynamics caveat: the current one-step legacy-unsym J3 `qvel` residual is about `0.001188`, while the no-frictionloss isolation gate is below `0.001`.
- Do not register reference-tracking Digit environments in `locomotion.ALL_ENVS` until they can reset without `ref_path`.
- Use `learning/train_jax_l2t_digit.py` for Digit L2T training without registering ref-tracking envs globally. Keep L2T smoke runs deterministic with fixed refs, `--suppress_training_stdout`, and JSON outputs (`metrics.json`, `progress.json`, `env_config.json`, `train_config.json`).
- Dynamics tests should not depend on reference trajectory data.
- Preserve legacy custom Digit helpers in `mujoco_playground/_src/locomotion/digit_v3/dynamics.py` when touching imported Digit environments. This includes PD stepping and actuator-force-to-joint-torque bookkeeping.
- Keep env-local `_get_act_joint_torques` methods as thin wrappers over `dynamics.actuator_joint_torques`; do not reintroduce copied actuator-force multiplication.
- Preserve Digit `make_data` warmstart parity: after `mjx.forward`, `qacc_warmstart` is set from `qacc` to match old MJX reset behavior.
- Preserve the same warmstart normalization in native MuJoCo probe rollouts; otherwise native old/new engine comparisons can include a reset warmstart artifact.
- Treat Digit domain randomizers in `mujoco_playground/_src/locomotion/digit_v3/randomize_*.py` as custom dynamics code too; they mutate mass, inertia, friction, armature, damping, and related model fields.
- Treat per-env action-delay buffers, push disturbances, Kp/Kd scaling, motor-strength scaling, and reset qpos/qvel noise as part of the old Digit dynamics/control surface.
- For old/new Digit debugging, prefer CPU, no JIT, `impl=jax`, a fixed `--seed`, pinned `ref_idx=0`, and zero actions before trying long training runs. `learning/digit_env_probe.py` defaults to zero action; keep explicit `--action_mode=zero` in Pixi tasks for readability.
- To rule out PPO, start with zero-action env probes before any PPO probe. Use one-step probes for tight parity and `probe-digit-*-rollout16-cpu-nojit` for short-horizon accumulation.
- Use `gate-digit-dynamics-diagnostics` when specifically auditing raw JAX dynamics; it chains the normal legacy-unsym dynamics gate and the no-frictionloss isolation gate.
- Use `gate-digit-jax-dynamics-parity` for the guarded one-step old/new JAX dynamics check; it runs the old stack, migrated legacy-unsym stack, compare, and final package-data check.
- Use `gate-digit-jax-dynamics-x64-parity` when you need the one-step raw JAX state/control residual under the practical `0.001` line. It enables `JAX_ENABLE_X64=true` in both old and migrated probes and guards final qvel and ctrl under `0.001`; treat it as a diagnostic path, because final `qfrc_constraint` still differs by about `0.189`.
- Treat `compare-digit-legacy-unsym-cpu-nojit` and `compare-digit-legacy-unsym-rollout16-cpu-nojit` as guarded JAX parity gates. They require fixed seed `0`, zero actions, no rollout contact mismatch, bounded final reward, and bounded final qpos/qvel/qfrc residuals.
- When the one-step JAX dynamics gate shows a J3 `qvel`/`ctrl` residual, use `--include_substep_trace --include_arrays`; current trace evidence shows model arrays and substep-0 PD control are identical, and the J3 control drift appears only after MJX integration creates a J3 velocity-error residual. The trace includes `pre_euler.euler_damping`; current J3 evidence shows qM/qLD diagonals are effectively identical while substep-2 frictionloss `Jaref`/force split makes hidden Euler qacc differ by about `1.65`.
- For first-batch PPO diagnostics, keep `--seed` fixed and keep `--step_action=zero` when judging environment parity. Compare zero-action PPO probes with `--require_zero_ppo_actions` so the run fails if either stack accidentally steps sampled or nonzero actions. Check the `PPO isolation summary`: `step.action` and `ppo_loss.raw_action` must be zero, and `policy.raw_action(sampled_not_stepped)` is only policy-sampling noise.
- Use the model-only probe before PPO when dynamics drift appears: `probe-digit-new-model-cpu-nojit`, `probe-digit-old-model-cpu-nojit`, then `compare-digit-model-cpu-nojit`.
- Use the native MuJoCo probe to distinguish MJX drift from MuJoCo engine-version drift: `probe-digit-new-native-cpu-nojit`, `probe-digit-old-native-cpu-nojit`, then `compare-digit-native-cpu-nojit`. For short-horizon native checks, use `probe-digit-*-native-rollout16-cpu-nojit`; these pass `--skip_mjx_rollout` so the probe records reset but does not waste time stepping MJX.
- Use the same-state native replay when contact divergence appears: first produce the rollout16 JSONs, then run `probe-digit-*-native-same-state-step2-cpu-nojit` and `compare-digit-native-same-state-step2-cpu-nojit`. Current evidence shows old MuJoCo 3.2 produces 7 contacts while new MuJoCo 3.9 produces 4 or 5 contacts from identical saved step-2 `qpos`/`qvel` with zero action.
- Use `--native_mj_option_override` for native-only contact experiments that old MJX cannot import, for example old MuJoCo `enableflags=80` (`mjENBL_NATIVECCD | mjENBL_MULTICCD`). Do not use `--mj_option_override` for those native-only checks because it rebuilds MJX.
- Use `--native_geom_override` for probe-only contact geometry experiments, for example `left-foot.margin=0.001`; it only changes the copied native MuJoCo rollout model and must not be treated as a migrated-env fix unless rollout summaries improve broadly.
- Use `gate-digit-no-frictionloss-cpu-nojit` to isolate the current dominant JAX drift source. It disables frictionloss on both old and new probes and guards zero action, contact consistency, final `qvel < 0.001`, final `qfrc_constraint < 0.01`, and final `ctrl < 0.001`. For accumulation without PPO, use the matching `probe-digit-*-no-frictionloss-rollout16-cpu-nojit` tasks and `compare-digit-no-frictionloss-rollout16-cpu-nojit`.
- Use the substep trace to inspect the dominant active-set split: `probe-digit-new-trace-cpu-nojit`, `probe-digit-old-trace-cpu-nojit`, then `compare-digit-trace-cpu-nojit`.
- Use `jax_legacy_newton_unsym` only for migrated JAX compatibility/parity runs; it restores the old unsymmetrized Newton Hessian Cholesky path and removes the dominant frictionloss active-set split. Keep probes, PPO, and L2T routed through this shared Digit config flag rather than adding separate solver patch paths.
- Keep Warp as the primary Digit backend. The legacy Newton patch is process-local and intended for old/new JAX comparisons and parity training smoke tests.
- The compare script starts with metadata/version summaries, compact rollout summaries (`max_action_l2`, initial/final reward, qpos/qvel/ctrl, solver-force fields), contact summaries (`ncon`, pair-count L1, named old/new pairs), contact-point tables, and a PPO isolation summary before printing the largest diffs; use these to confirm zero-action probes really ruled out PPO and to separate reset residuals, contact-manifold splits, and accumulated rollout drift. It reports array shape mismatches explicitly and annotates contact shape mismatches with contact pair counts. The probe records active `contact_geoms`, including native-model copies after native-only option/geom overrides.
- Do not treat new MuJoCo native CCD flags as native parity fixes. Current native rollout16 evidence shows `disableflags=524288` (`mjDSBL_MULTICCD`), `disableflags=131072` (`mjDSBL_NATIVECCD`), and `disableflags=655360` combined all leave the foot-floor contact split and final native residual unchanged.
- Do not treat new MuJoCo `mjDSBL_MIDPHASE` as a native parity fix. Current same-state replay evidence shows `disableflags=16384` leaves `native_source_rollouts` identical to new/default.
- Do not treat migrated foot `geom_margin` tuning as a parity fix; current native rollout16 evidence shows `margin=0.001` lowers final `qpos` max diff but worsens final `qvel` and `qfrc_constraint`, while `margin=0.005` creates initial native contacts and much larger force drift. Tiny same-state margins (`1e-9`, `1e-6`, `1e-4`) also leave the new next-step contact counts unchanged.
- Do not treat migrated foot box height tuning as a parity fix. Current same-state replay shows `geom_size[...,2]=0.0108` or `0.0110` can reduce one-step force drift, but native rollout16 rejects it: `0.0110` slightly improves final qpos/qvel while worsening final `qfrc_constraint` to about `6.44` and `qacc_smooth` to about `493`.
- Do not treat migrated-only solver iteration tuning as a parity fix unless both reset and first-step probes improve; current evidence shows it trades reset parity for first-step parity.
- Do not treat migrated-only `ls_iterations` changes or `dof_frictionloss` scaling as parity fixes; current evidence shows they also trade away reset parity.
- Use the first-batch PPO probe for fast training-stack checks; full PPO with `JAX_DISABLE_JIT=true` is too slow to be a useful debug loop.
- For single-trajectory PPO parity debugging (`num_envs=1`, short `unroll_length`), treat observation normalization as an amplifier, not as dynamics evidence. Current evidence shows tiny old/new state drift can push running-stat std to the `1e-6` clip in one stack but not the other, producing huge normalized-observation/logit drift. Use `--normalize_observations=False` when checking PPO update parity with one trajectory, then re-enable normalization only for broader training-style runs.
- Use `gate-digit-ppo-first-update-no-obsnorm` as the fast guarded single-trajectory PPO update gate, then `gate-digit-ppo-single-traj-no-obsnorm` for the slower four-update gate.
- When checking actual policy behavior across a few PPO iterations, run `gate-digit-ppo-single-traj-policy-probe`. This compares deterministic 32-step policy rollouts emitted from the PPO `policy_params_fn` callbacks; old Brax may omit the new stack's step-0 probe, so compare common callback steps. Treat action diffs and per-step reward-mean diffs below `0.001` as acceptable policy parity; cumulative reward sums scale with probe length.
- For normalized first-update diagnostics, avoid cross-JAX reference-sampling drift by using `--force_ref_indices` with one ref per env lane. The current normalized 16-lane diagnostic gate uses `--normalizer_std_floor=0.001`; treat this as a stability diagnostic for running-stat amplification, not as proof that default normalized full training is aligned.
- For full PPO normalized smoke with multiple refs, use `ppo-digit-old-jax-forcedrefs-floor1e-3-smoke`, `ppo-digit-new-jax-forcedrefs-floor1e-3-smoke-legacy-unsym`, then `compare-digit-ppo-forcedrefs-floor1e-3-smoke-legacy-unsym`. This exercises the real Brax `ppo.train` path with deterministic lane refs, the diagnostic std floor, and the practical `0.001` training-metric tolerance.
- For the longer normalized PPO gate, `gate-digit-ppo-forcedrefs-floor1e-3-4updates` is acceptable when all training metric diffs stay below `0.001`. Use `gate-digit-ppo-forcedrefs-floor1e-3-8updates` when you need a longer controlled PPO curve; current evidence stays under `0.001` through step 2048, with final total/policy drift around `6.8e-4`. Use `gate-digit-ppo-forcedrefs-floor1e-2-4updates` when a stricter sub-`2e-4` diagnostic is needed; current evidence has no compare failures, final total/policy drift around `9.5e-6`/`9.7e-6`, and largest progress drift around `2.6e-5`. These gates match training callbacks by `num_steps` because old Brax may emit an extra eval-only callback at step 0.
- For L2T parity smoke, prefer `gate-digit-l2t-forcedrefs-floor1e-3-mode-detinit-no-advnorm` over the sampled one-step smoke. It uses forced lane refs, teacher mode actions, deterministic network init, no entropy, no advantage normalization, push perturbations disabled, the diagnostic std floor, and the practical `0.001` training-metric tolerance.
- PPO/L2T parity tasks that pass `--suppress_env_stdout --suppress_training_stdout` intentionally quiet reference-loader chatter while preserving runtime stderr warnings from the training section.
- Use `--zero_network_params` in the first-batch PPO probe when policy/value initializer drift is a confounder. Pair it with `--entropy_cost=0.0` to isolate Digit env dynamics from old/new Brax distribution entropy differences; only use `--step_action=sample` after the zero-action path is understood.
- Treat `gate-digit-ppo-first-batch-zero-params-no-entropy` as the strict PPO rule-out gate. It must keep `step.action` and `ppo_loss.raw_action` at zero and keep zero-param/no-entropy PPO loss drift below the Pixi task thresholds. Use the underlying old/new/compare tasks only when debugging one side.
- For full PPO smoke after the strict gate, prefer the zero-initialized no-entropy tasks (`ppo-digit-old-jax-smoke-zero-init-no-entropy`, `ppo-digit-new-jax-smoke-legacy-unsym-zero-init-no-entropy`, then `compare-digit-ppo-smoke-legacy-unsym-zero-init-no-entropy`). These use fixed `--seed`, `--zero_network_init`, deterministic eval, pinned `ref_idx=0`, and `entropy_cost=0.0` to control initializer and entropy drift while keeping the real PPO loop.
- When the PPO loop itself should run but Digit must receive zero actions, use `--rollout_action_mode=zero` through the `*-force-zero-zero-init-no-entropy` smoke tasks. This is a diagnostic env-step override, not a normal training setting. The forced-zero compare task is guarded: it requires matched configs/progress, `rollout_action_mode=zero`, `training/total_loss` and `training/v_loss` drift below `1e-8`, policy/entropy loss drift below `1e-12`, and eval reward drift below `5e-4`. Current forced-zero smoke evidence keeps the eval reward diff at about `0.000399` and matches PPO `training/total_loss` within about `2.2e-9`.
- Use `--suppress_env_stdout` for `learning/digit_env_probe.py` tasks so old Digit reference-debug prints and loader progress bars do not hide the JSON output path.
- Use `--suppress_training_stdout` for direct PPO smoke tasks so old Digit per-step reference debug prints do not flood the terminal.
- Use `compare-digit-ppo-smoke`, `compare-digit-ppo-smoke-legacy-unsym`, and `compare-digit-l2t-smoke` to compare smoke logs. These tasks must require matching train configs and matching progress callback counts/steps; only `jax_legacy_newton_unsym` is an allowed env-config difference for legacy-parity runs. Check the `Train config summary` first so `seed`, `force_ref_idx`, and batch/update settings are visibly matched. Treat smoke metric drift as training-stack evidence unless the zero-action first-batch probe also shows an env dynamics drift.
